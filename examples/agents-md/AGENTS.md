# AGENTS.md

> Instructions for AI coding agents (Claude Code, Cursor, Codex, Copilot, Gemini CLI, etc.) working in this repository.

## Core Commands

```bash
# Install dependencies
pnpm install

# Run all tests
pnpm test

# Run a single test file
pnpm test path/to/file.test.ts

# Type check
pnpm typecheck

# Lint and format
pnpm lint
pnpm format

# Dev server
pnpm dev

# Production build
pnpm build
```

If a command fails, fix the underlying issue. Do not skip failing tests or disable lint rules to make the build pass.

## Tech stack

- TypeScript 5.5+ in strict mode
- Next.js 15 (App Router only — do not use Pages Router)
- React 19
- Tailwind CSS for styling
- Vitest for testing
- pnpm for package management (not npm or yarn)

## Code style

Follow the existing code, not abstract style guides. Concrete rules:

- Single quotes for strings: `'hello'` not `"hello"`
- No semicolons at end of statements
- 2-space indentation
- Functional components with hooks; no class components
- Named exports preferred; default exports only for Next.js page/layout files
- Async/await over `.then()` chains

Real example of the style we want:

```typescript
import { type User } from '@/types'

export const fetchUser = async (id: string): Promise<User> => {
  const response = await fetch(`/api/users/${id}`)
  if (!response.ok) {
    throw new Error(`Failed to fetch user: ${response.status}`)
  }
  return response.json()
}
```

## Always do

- Run `pnpm typecheck` and `pnpm lint` before considering a task complete
- Write tests for new functions in the same commit
- Match the import order of existing files: external packages, then `@/` imports, then relative imports
- Use the existing logger (`@/lib/logger`) instead of `console.log`

## Ask first

- Adding a new dependency (we have a strict policy on bundle size)
- Changing the database schema (we have migration conventions)
- Modifying authentication or authorization logic
- Touching anything in `/billing/` or `/payments/`

## Never do

- Modify files in `/migrations/` (these are append-only)
- Modify files in `/generated/` (auto-generated by codegen)
- Add `any` or `as unknown` to suppress TypeScript errors — fix the underlying type
- Commit secrets, API keys, or `.env` files
- Use `git push --force` on the main branch

## PR conventions

- Title format: `[scope] Description in imperative mood`
  - Good: `[auth] Add OAuth provider for GitHub`
  - Bad: `Added new OAuth thing`
- Required checks before merge: `lint`, `typecheck`, `test`, `build`
- Squash merge only — no merge commits on main
- Reference the issue number in the PR description: `Closes #123`

## Domain vocabulary

- "Workspace" = a tenant in our multi-tenant architecture (not a folder)
- "Account" = a billing entity (one workspace = one account)
- "User" = a person, can belong to multiple workspaces

# Why this is a notable example

This file demonstrates the patterns GitHub's 2,500-repo analysis identified 
as highest-impact:

1. **Commands first.** The very top of the file. Agents need to know how to 
   build/test/lint before they need to know your code style.
2. **Three-tier rules** ("Always do" / "Ask first" / "Never do") give the 
   agent clear behavioral boundaries.
3. **Real code example** in the style section — far more useful than abstract 
   description like "use functional style."
4. **Explicit "ask first" list** prevents agents from making changes in 
   sensitive areas without checking.
5. **Domain vocabulary section** disambiguates terms that might mean 
   different things in different contexts.
6. **Under 150 lines** — this gets read on every task, so keeping it tight 
   matters for the agent's token budget.
